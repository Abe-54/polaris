# Reviewer

The Agent layer of a Risk Summary (CONTEXT.md: Reviewer, Risk Summary, Risk Finding), and the module that runs whole Risk Summaries: the Rules (`../rules/`), then the Reviewer, then the cost line and the end. Decisions: Linear ENG-185, ENG-222 (the Reviewer), ENG-225 (Verdicts, `.polaris/review.md`), ENG-229 (cost line). Verdicts themselves are decided in `../engine/review.ts` and stored in `../store/review.ts`.

## Interface (`index.ts`)

- `Reviewer` (`ReviewerLive(options)`; the tag lives in `service.ts`): `run`, `runAutomatic`, `ask`, `settings`, `setSettings`. Served by `ReviewerRpcs.ts`: `review.runRiskSummary`, `review.askFinding`, `review.reviewerSettings`, `review.setReviewerSettings`.
- `ReviewerSessions` and `ReviewerPolicyLive` (`policy.ts`): the Reviewer's sessions, and the Engine's `ApprovalPolicy` that answers their approvals. Provide one `ReviewerSessions` to both (see `../transport/serve.ts`).
- `automaticRun` and `followAutomatic` (`automatic.ts`): what starts a summary without a Client asking, and the store subscription that starts it.

**Loaded on first use.** The Daemon mounts `../transport/lazyReviewer.ts`: from start it registers the Reviewer's sessions (`registerReviewerSessions`, for the policy) and follows the automatic runs, both from light modules; `index.ts` and the rest load on the first run or request. A restart that left a summary or a walkthrough running (`needsReviewerStartup`) loads it at once, so recovery fails them before Clients connect.

## A Risk Summary

1. **Range** (`range.ts`). A pull request reads its Review Checkout: `mergeBase..head`, Rules in `history` mode, cached under `(repoKey, mergeBase, head)`. With `since` (the head reviewed before), the interdiff (`ReviewCheckoutGit.interdiff`) gives the base, Rules run in `snapshot` mode, and the key carries `since`; when the interdiff can't be built, a full summary runs with its reason as the note. Agent Session Turns are keyed by the Workspace path and their first before- and last after-checkpoint, but reviewed as the Review shows them: `compose.ts` builds two trees from each Turn's own diff (every file the Turns touched, from before the first Turn that touched it to after the last), so commits that landed between Turns (a merge, a pull, someone else's work in the checkout) are never the session's. The Rules, the prompt and follow-ups all read those trees.
2. **Plan** (`when.ts`). "When it runs" (`onPullRequests`, `onSessions`) and "Ask first for large changes" (`askAboveLines`, added + removed lines) decide whether the Reviewer runs now. A switch that is off leaves the agent layer `skipped` with a note; a change over the threshold (decided before the summary starts) ends it `completed` with the agent layer **`pending`** and a note: that is "waiting for Run reviewer". `RiskSummary.reviewer` names a Reviewer only when one runs; a failed one's layer note gives the reason (the session's failure, or the error). `refresh: true` means the user asked ("Run reviewer", a rerun), so neither applies. The Rules always run.
3. **Cache.** An existing summary for the key is answered unless `refresh` is set, it failed, or it skipped the Reviewer and this run wouldn't (a Turn's Rules-only summary when the session opens in Review; a switch turned back on). Starting is serialised, so two Clients opening the same Review share one run.
4. **Start.** `RiskSummaryStarted` with the resolved Reviewer (or the agent layer `skipped` with the Rules-only note); the call returns, and the rest runs in the module's scope.
5. **Rules** (`recordRulesLayer`), so the Reviewer sees their Findings.
6. **Reviewer** (below), then `RiskFindingsRecorded` and the layer's end.
7. **One view across new commits** (`merge.ts`). An incremental summary then carries the previous summary's open and dismissed Findings forward (the newest completed summary of the head it follows, `riskSummariesAt(repo, head)`), each re-anchored where its flagged lines now are (whitespace-normalised, nearest the old place). One whose code is gone is recorded Resolved as `fixed`; one the new run found again (same identity) isn't carried twice. So the newest summary of a Review is always the whole picture.
8. **End.** `RiskSummaryEnded` with the `ReviewerRun` (its session), the cost and any note; `failed` only when both layers failed. A pull request's checkout then records the head as reviewed (`Engine.checkoutReviewed`).

**When it runs.** The Client calls `review.runRiskSummary` when a Review opens (with the PR's `ReviewContext`, since the Daemon has no GitHub token), and the cache makes that idempotent. The Daemon runs one on its own (`automaticRun`): **the Rules after every Agent Session Turn** (`TurnEnded`, that Turn alone, agent layer skipped with `RULES_AFTER_TURN`; nothing when the Turn changed no file, and never for the Reviewer's own sessions), when Turns are accepted (`TurnsAccepted`: the session through that Turn) and when a reviewed checkout moves to a new head (`ReviewCheckoutChanged`, ready, `head ≠ reviewedHead`: only the new changes).

## The Reviewer's session

- **An ordinary Agent Session** started through the Engine (`session.ts`): placement `ReviewCheckout` (or the Workspace for an Agent Session's Review), permission mode `supervised`, titled "Reviewer · Pull request #12" (or "Reviewer · <session title>"). It shows in the Orchestrator, its Usage counts like any session's, and follow-ups continue it. "Only the new changes" continues the previous summary's session, which already knows the change.
- **Read-only, no prompts** (`policy.ts`): `OpenOptions.readOnly` fixes Codex to `approvalPolicy: "never"`, read-only sandbox, network off on thread start/resume and every Turn, including inherited Subagents. A permission mode change never widens it. Claude uses `dontAsk`, read/search/Agent tools and sandboxed Bash, with writes denied at `/`, all network domains denied, no unsandboxed commands, no settings hooks or MCP servers. Where Claude Code's sandbox can't start (Linux without bubblewrap or socat), `reviewerShell` is `none`: the Reviewer gets no Bash at all, only Read/Glob/Grep/Agent, its prompt says so, and the Risk Summary's agent layer notes the Host and the install command (ADR 0042). Any late server request or permission callback is declined immediately; the Engine policy also declines every escaped request before it reaches Needs You or the log. Tests, lint and typecheck may run only inside that sandbox, and commands that need writes or network fail there.
- **Context** (`prompt.ts`): what the Reviewer may do; every changed path with its status and +/− (`changedFiles.ts`, shared with the Walkthrough); the PR's title and description, or the session's prompts; `.polaris/review.md` as committed at head, then `~/.polaris/review/<host>/<owner>/<name>.md` (`instructions.ts`); the Rules' Findings (not to be repeated); the diff (whole files up to 240k characters, the rest listed to read with git); the output contract. Generated files (`generated.ts`: built-in patterns, `.gitattributes` `linguist-generated` or `-diff` and the front-matter's `ignore:` globs, read at a PR's base so it can't hide its own code, or an Agent Session's working tree) are tagged `[generated]` in the list and their patches are never sent; `git.diff` flags the same files for the Client.
- **Completion and restart** (`session.ts`, `recovery.ts`): a Turn has a 30-minute deadline; expiry interrupts it and fails the layer. At startup the Reviewer restores its session identities (completed summaries plus in-flight Reviewer prompts) and marks abandoned summaries failed with a rerun note, preserving finished layers and Findings. It does not resume lost workers or change Engine/store recovery. Failed summaries are not cache hits.
- **A Harness that couldn't run** (`launch.ts`): when every command the Turn ran printed only the sandbox's own one-line error (`bwrap: …`, Codex's `error building bubblewrap command: …`, `sandbox-exec: …`) and exited as that tool does, the sandbox never started, so the layer fails with that line, the Host and what to try. The Findings the Reviewer still returned are kept, so a reviewed script that prints the same line can't hide them (ADR 0055, ENG-758). A Harness whose binary isn't on the Daemon's PATH fails its session's start, and the layer's note carries the driver's words (Codex names the Host and the PATH it searched).
- **Output** (`output.ts`): one fenced JSON document matching `ReviewerOutput` (its JSON Schema is in the prompt), decoded with Effect Schema; prose is never read. A reply that doesn't decode gets one repair Turn. Each Finding must overlap a hunk of the diff on its side (`diff.ts`), or it is dropped and counted in the layer's note. Identity: `agent`, the path, the flagged code and two lines either side, whitespace-normalised.
- **Follow-ups** (`ask.ts`): `review.askFinding` registers the session with the policy (after a restart too), sends the question, answers with the Turn's id once recorded, and after the Turn records what the reply changed: new Findings, revised ones (by id, its own only) and withdrawals (`RiskFindingResolved`, `withdrawn`).

## Settings (`settings.ts`)

`~/.polaris/reviewer-settings.json`: `{ default, workspaces, onPullRequests, onSessions, askAboveLines }` (the last three default to true, true, 2,000 and are host-wide), written atomically. Resolution: the Workspace's override, else the default, else the first ready of Claude Code `claude-opus-5-5` `high` and Codex `gpt-6.1-sol` (from `Availability`), else none: the agent layer is skipped and the summary's note says "Rules only…".

## Cost and Plan Limits (`cost.ts`)

The cost line is the Reviewer session's Usage since the summary started (`UsageIndex.query` by session, after a refresh): input, cache and output tokens, and the Harness-reported cost where there is one (null otherwise; the Client may estimate). When the Reviewer's Harness has a Plan Limit at `warning` or `reached`, the summary's note says so; the review still runs, with no automatic downgrade.

## Performance

Nothing runs until a summary is asked for or a Turn ends: the module holds one store subscription (filtered to `TurnEnded`, `TurnsAccepted` and `ReviewCheckoutChanged`), no timers or watchers. A Turn that changed files costs one Rules run on its diff (a `git diff --quiet` first; see `../rules/README.md` for the scanners); an unchanged Turn costs that one git call. A run costs the Rules (see `../rules/README.md`), two `git diff`s and a `git show` per Finding, and the Harness.

## Tests

`bun test src/reviewer`: the policy's allow and deny lists, diff ranges and the reply's decoding and validation, identities across line shifts, instructions and their front-matter, settings resolution and persistence, the Plan Limit note, and end to end on the real Engine, store and Review Checkout git over a local code host with a fake Harness answering like the bench Reviewer: a pull request reviewed in its own session (approvals answered by policy, none recorded), the cache, a follow-up withdrawing a Finding, new commits reviewed on their own in the same session, and Rules only without a Reviewer. The bench Harness (`../harness/bench/review.ts`) answers any Reviewer prompt with schema output, so benchmarks and the dev Desktop App run whole Risk Summaries without tokens.

## Walkthrough

A separate read-only Agent Session writes the three-section Markdown alongside the Reviewer, on the same composed change. `walkthrough.ts` persists full and delta metadata on the existing Risk Summary events, without changing the Reviewer layer or Session State machine. Full Markdown is shared by `(repo, mergeBase, head)` across Reviewer refreshes; a head move also writes only `previousHead..head`. The existing `review.watchRiskSummary` feed streams updated summaries, as for Reviewer progress. Partial Markdown is committed at section boundaries, not per token; all Runs use the existing approval/sandbox/no-network policy.

Optional `ReviewerSettings.walkthrough` contains `enabled` and nullable Harness/Model/Effort overrides, with missing/null choices falling back to the Reviewer. The ask-first threshold gates both; explicit `review.runRiskSummary` with `refresh: true` runs both. `review.runWalkthrough { summaryId, context? }` writes/retries an unfinished walkthrough; ready heads remain cached. `review.stopWalkthrough { summaryId }` sends `Interrupt` through the Engine and records a stopped reason. Daemon startup retains partial Markdown as failed, restores the read-only session registry from logged prompts and waits for explicit Retry; it never resumes a Turn automatically. `review.walkthrough` gates the new RPCs. Session-Turn summaries also carry optional `prompts` from the event log, including per-Turn reported FileChange counts.

The prompt adapts the pinned MIT humanlayer/skills visual-pr and show-me formats; see `ATTRIBUTION.md`. It passes open Finding ids and asks for `[title](finding:<id>)` links and inline file references. Harness errors retain their own evidence line. Usage supplies token totals where available. File-read progress remains zero when a Harness does not report reads; `filesTotal` counts diff files.
