Short secrets follow the Lead's answer 713: four or more characters match substrings;
one to three characters match whole values or tokens bounded by non-word characters.
Credential syntax is always scrubbed. The shared function documents this rule, so the
Desktop's producers use the same behavior. Matching URLs remain internal and are never
used to connect. Unprobed sources retain absent `reachable`.

MySQL SHOW/DESCRIBE/EXPLAIN use X's agreed fail-closed policy (ENG-667). SHOW TABLES returns
E-DATA-SQL with guidance mentioning `describe`, per the Lead's answer 681.

## Verification

Sixteen deliberate fix-removal checks were detected, covering every RM finding. Source files
were restored in `finally` after every mutation. F1 removed the production shared Data
Layer and the native Postgres test failed with missing DataSources. F7 removed Claude's
signal forwarding and the wait failed its deadline; F13 removed resubscription and the
later-event test failed its deadline. The other mutations failed their outcome assertions. Two extra checks removed the Engine reactor itself and restored the quadratic scanner: the former missed the outside Query Log entry, and the latter took 1,143 ms on 100k dotted characters against the 500 ms regression ceiling.
The script and logs are temporary evidence in `/tmp/mx-mutations.py`,
`/tmp/mx-mutations-final.log` and `/tmp/mx-mutant-F*.log`; they are not product files.

The native tests each create an isolated POLARIS_HOME and an `mx_UUID` schema (Postgres)
or table (MySQL), then remove only that fixture. They use real production Engine services,
source discovery, approval projection, read execution and MCP HTTP. Fixture user approval
is recorded through `decideSession`; listener ownership and production policy are preserved.
A bare selected password is returned in an innocuous column and embedded in a database
error; neither text nor structured output exposes it. Query Log author/Turn attribution
and outside-command reactor persistence are asserted.

The sandbox refused database connections and listener binds. The Lead ran both real
database tests natively and reported both passing (answer 708); the first MySQL run exposed
the incorrect SHOW error expectation, now corrected. Native HTTP cancellation passed after
repairing the fixture's source-list assertion. Final restored-code receipts accompany the Claim.

No live Harness/model session, Desktop rendering, native Linux listener probe or Apalache
run is claimed. The Engine edit only restarts a best-effort subscriber; command decisions,
events, acknowledgments and Session lifecycle are unchanged. No idle timer or polling was
added. Existing Lead-owned native idle acceptance remains the performance gate.

forwards the internally returned approval id to query/describe; the MCP input schemas
reject a caller-supplied id. This optional internal field is compatible with the accepted
X base and prepares XF's one-request grant consumption. XF owns the grant semantics;
MX's added boundary regression proves the retry forwards the real id and rejects forgery.
