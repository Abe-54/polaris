# Adversarial review: D, Data Source discovery, manual sources and labels (ENG-644)

Reviewed: `981eb45b` (merged in `5bfef92f` on `polaris/grill-with-docs-i-want-to-do-7ce3`), diffed
against its parent. M's consumers (`075b52e3`) were read where the Lead's questions reach them.
Read against ADR 0091, `docs/specs/data-tools-v1.md` and `apps/daemon/src/data/README.md`.
Reviewer: RD, Opus 5.5, 2026-10-30. No product code changed.

**Verdict.** The core safety property holds: for every hostile URL tried, the endpoint Bun.SQL
dials is the one the metadata shows, and Host PG* variables can't redirect it. No project code
runs. Errors are constant text. Secure Storage's other namespaces are untouched. The problems are
around that core. A checkout can take the Daemon down with one symlink (F1). Locality is decided
by the string `127.0.0.1`, so a tunnel to production reads with no approval (F2, which the brief's
rule makes P0; it needs a Lead/user decision). Labels stay on a name after the target moves (F3).
`.env.example` and `.env.production` override `.env` (F4).

### F1 · P1 · Unbounded, blocking reads

`read()` is `readFile(join(checkout, file), "utf8")` with no size limit, no `lstat`, and no check
that the target is a regular file. Every `list`, `resolve` and watch snapshot re-reads every file,
inside `lock.withPermit`, and the lock is one `Semaphore(1)` shared by every checkout on the Host.

Failing scenarios (repro R3):

- `compose.yaml -> /dev/zero` (git stores symlinks, so a cloned repo can carry it): RSS 2.4 GB at
  0.5 s, 3.4 GB at 2 s, killed by the watchdog. Opening Data (⌘4) or one `data_sources` call
  would take the Daemon, and every Agent Session on the Host, down. On a Raspberry Pi 4 it's
  immediate.
- `compose.yaml` as a FIFO (an agent can `mkfifo` in its own checkout): `discover` never returns.
  Because the lock is held, every later Data request for *every* checkout on the Host hangs too.
  `Effect.tryPromise` can't interrupt the read.
- A 2 GiB sparse `.env.big`: 2.2 GB peak RSS per call. The read fails past the string limit and
  is swallowed, so the cost repeats on every request. 600 MiB reads succeed at 700 MB RSS.

Severity: P1. It's a Host-wide denial of service from untrusted repository content, not a leak.
Suggested fix: `lstat` each path, then read only regular files under a small cap (64 KiB is
generous for these formats), opened with `O_NOFOLLOW|O_NONBLOCK` and bounded by `read` length. Do
discovery outside the lock (it only needs the lock for SQLite and Secure Storage), and put a
timeout on it.

Held: a symlinked `.env*` is already skipped, because `Dirent.isFile()` is false for symlinks.

### F2 · P0 (design) · Loopback isn't local

`localHost` returns true for `localhost`, `::1`, any `127.*` literal and any path starting with
`/`, and `access` becomes `read` with no approval. Tunnels expose remote production on exactly those
addresses: `pscale connect` (127.0.0.1:3306), `cloud-sql-proxy`, `kubectl port-forward`,
`fly proxy`, `ssh -L 5432:prod:5432` and `ssh -L /tmp/pg.sock:prod:5432`. These are common in the
very projects that discover a `DATABASE_URL`.

Failing scenario: `.env` has `DATABASE_URL=postgres://app:pw@127.0.0.1:5432/app`, and the
developer runs `cloud-sql-proxy` on 5432. `data_sources` lists `app local … access read`.
`describe` and `query` read production rows into the agent's context without asking.

Severity: the brief says that misclassifying remote as local is P0. D can't see a tunnel from the
URL, so this is a product decision for the Lead and user, not a code bug. Options, cheapest first:

1. Find which process owns the listening port. On macOS use
   `lsof -nP -iTCP:<port> -sTCP:LISTEN -Fc` (or `proc_pidinfo`); on Linux, `/proc/net/tcp{,6}`
   inode → `/proc/*/fd`. For a Unix socket, check the owner of the socket inode. Treat the source
   as `remote` unless the owner is `postgres`, `mysqld`, `mariadbd`, or Docker's/OrbStack's
   port proxy for a compose service in this checkout. Do this at resolve time, not on a timer.
2. Treat only compose-published ports, and sockets owned by a database server process, as local.
   Ask for approval on every other loopback target the first time.
3. Keep the current rule, and say in the approval copy and DESIGN.md that "local" means
   "loopback", not "your own data".

### F3 · P1 · A label survives a target change

`id = SHA-256(checkout ␀ name)`. Labels (and anything else keyed by `id`) stay with the *name*.
Discovery re-reads files on every request, so the target behind a name can change between two
calls, and an agent can edit `.env.local` in its own checkout.

Failing scenario (repro R4, S8): the user labels discovered `app` (localhost) `SCRATCH`/`none`.
Then `.env.local` sets `DATABASE_URL=postgres://u:p@prod.example.com:5432/app`. Afterwards `app`
is `remote prod.example.com label=SCRATCH/none`, with the same id `f35e6b9a…`. The red REMOTE cue
is replaced by the user's calm label.

`access.ts` says X keys remembered approvals "by the exact target". That has to hold, and X must
compare the target again at execution: `resolve` re-reads, so a target approved at one moment can
be a different one when the query runs. Suggested fix: store a target fingerprint
(`engine, host, port, database, user, path`) next to each label. When it no longer matches, drop
the override (or show it as stale) and fall back to `defaultLabel`.

### F4 · P1 · Other `.env.*` files override `.env`

`envRank` gives every suffix other than `development`/`local` rank 1, which is above `.env` (0).

Failing scenarios (repro R2):

- `.env` = internal DB, plus a committed `.env.example` with `postgres://user:password@localhost:5432/mydb`
  → `app .env.example -> local localhost:5432/mydb`. The real source vanishes and a placeholder
  replaces it.
- `.env` = local dev, plus `.env.production` = prod → `app .env.production -> remote prod.example.com`.
  Next.js, Vite and dotenv-flow never load `.env.production` in development. The agent's `app` is
  production, and the approval prompt asks about `app`, which the user believes is dev.

Suggested fix: read only `.env`, `.env.local`, `.env.development` and `.env.development.local`
(the README's documented order). List keys from `.env.production`, `.env.staging` and
`.env.test` as separate sources (`app (production)`), never as overrides. Ignore
`.env.example`, `.env.sample`, `.env.template`, `.env.vault` and `.env.keys`.

### F5 · P2 · Password text can reach metadata, and the scrubber misses `?password=`

1. An unencoded `/` in a password whose leading part looks like a port:
   `postgres://app:9876/hunter2@db.example.com:5432/app` parses as host `app`, port `9876`,
   database `hunter2@db.example.com:5432/app` (repro R1). That `database` goes into every watch
   snapshot and `data_sources` line. M's `knownFromUrl` takes `URL.password` (here `""`), so
   `hunter2` isn't scrubbed. The same goes for `?dbname=` or a path carrying a URL
   (`…/postgres%3A%2F%2Fu%3Ahunter2%40prod` → `database: postgres://u:hunter2@prod`).
2. `parseConnection` honours `?password=`, but M builds its known-credential list from
   `resolved.url`'s userinfo only. The real password is never on the list, so a driver error or
   tool output that echoes it alone isn't scrubbed.

Suggested fix: reject a candidate whose `database`, `user` or `host` contains `@`, `/`, `:` or
`://` (RC F1 asked for `host` already). Build the scrubber's list from `connection.password`, the
one password the Daemon will send, not from the URL.

### F6 · P2 · "keep" sends a stored password to a different target

`updatePassword` keeps the password whenever none is supplied, whatever the host, port or user
now is. A plain save under an existing name (no `previousName`) replaces it silently.

Failing scenario (repro R4, S1): save `prod` → `prod.example.com`, password `PROD-SECRET`. Then save
`prod` again with host `127.0.0.1` and no password. The result is `prod local 127.0.0.1
access=read`, and `resolve` hands `PROD-SECRET` to whatever listens on 127.0.0.1:5432, with no
approval. A process run by an agent can be a fake Postgres that asks for cleartext auth.

Today only a `client` grant can call `data.source.save`, so it takes a user action. Suggested fix:
"keep" is valid only when engine, host, port and user are unchanged; otherwise require "set" or
"clear". A save without `previousName` whose name exists should fail (E-DATA name taken) rather
than replace.

### F7 · P2 · Symlinks outside the checkout are followed

Only `.env*` is checked with `isFile()`. `config/database.yml`, `prisma/schema.prisma`,
`compose.yaml`, `drizzle.config.*` and `<dir>/settings.py` are read through symlinks to files and
directories anywhere the Daemon user can read.

Failing scenario (repro R2): `config -> /tmp/rd/outside/config` discovers
`rails config/database.yml -> local localhost:5432/other_secret_db user=admin`. Another project's
credentials become a source in this checkout, readable without approval because it's local.
Suggested fix: `realpath` each file, and require it to stay inside `realpath(checkout)` (this
also covers F1's device files).

### F8 · P2 · Quadratic Prisma parse under the lock

`/datasource\s+(\w+)\s*\{([^}]+)\}/g` rescans to the end of the text for every unterminated
`datasource x {`. 300 KB takes 2.9 s and 600 KB takes 12.3 s (repro R3). The Django loop has the
same shape (5k nested entries take 239 ms). Combined with F1's lock, one file stalls Data for the
whole Host. Suggested fix: F1's size cap, plus a linear scan (`blocks()`) for Prisma.

### F9 · P2 · `reachable: false` reads as "down"

D always emits `reachable: false`, and the README defines it as "has not connected". The spec
(`data-tools-v1.md:51`) puts `reachable: boolean, error?` beside connect failures. M's
`structuredContent` carries `reachable: false` for every source, and nothing in the tool
description says it's unprobed. An agent reading `{locality: "remote", reachable: false}` will
reasonably say the database is down, or skip it. Suggested fix: make it optional, absent until a
connection has been tried (or `status: "unprobed" | "reachable" | "unreachable"`). Then set it
from X's real connects. Ask the Desktop which state it draws.

### F10 · P2 · `.env` parsing gaps

`unquote` handles `"…"` or a bare value with ` # comment`, but not both.

- `DATABASE_URL="postgres://a:b@localhost/x" # dev db` keeps the quotes, the URL fails, and the
  source disappears (repro R2). This is a common form.
- `DATABASE_URL=postgres://${DB_USER}:${DB_PASS}@${DB_HOST}:5432/${DB_NAME}` (dotenv-expand, and
  Next.js expands `$VAR`) lists as `remote host=${DB_HOST} db=${DB_NAME}` (repro R1). It's junk
  in the UI and an approval prompt for a host that doesn't exist.

Held: `export`, a BOM (`\s` matches U+FEFF), CRLF, single quotes, and passwords with spaces, `"`
and `@` all parse correctly. Suggested fix: strip an inline comment after a closing quote. Expand
`${VAR}`/`$VAR` from the merged env as dotenv-expand does, or skip any value that still contains
one (as `literalTarget` already does for code).

### F11 · P3 · `resolve` returns the raw URL

For discovered sources, `resolve().url` is the checkout's URL verbatim. It includes parameters D
deliberately ignores (`hostaddr`, `options`, `sslrootcert`, `target_session_attrs`), and the URL
form is exactly what lets PGDATABASE redirect Bun 1.4.4. M already uses it, for outside-command
matching and scrubbing. Suggested fix: rename it to `matchUrl` with a "never connect with this"
comment, or replace it with the parsed fields M needs.

### F12 · P3 · Manual MySQL Unix sockets fall back to TCP

`connectionUrl` stores a socket host as `?host=/path`, and only Postgres reads `host`. A manual
MySQL source with host `/tmp/mysql.sock` resolves to `hostname localhost, path undefined`, shown
as `localhost` (repro R5). Write `?socket=` for MySQL.

### F13 · P3 · Checkout identity is the raw cwd string

Isolation holds: two sessions see each other's sources only when their `session.cwd` strings are
equal. But:

- A worktree path that is reused after removal inherits the old checkout's manual sources, labels
  and Secure Storage passwords.
- Nothing removes `data/<id>` entries or SQLite rows when a checkout goes away.
- `/repo` and `/repo/`, `/tmp/x` and `/private/tmp/x`, and `Repo` and `repo` on APFS split one
  checkout.
- A rename whose metadata transaction fails after the password copy leaves `data/<newId>`. A later
  save of that name with "keep" silently picks it up.

Suggested fix: `realpath` the cwd, prune on worktree removal, and remove the copied entry when
`storage.save` fails.

### F14 · P3 · Watch snapshots go stale on file edits

As documented, watch only re-emits on Daemon-side mutations. After a `.env` edit, the Desktop can
show `LOCAL` while `resolve` (and the approval) already sees the remote target. Re-list on Data
focus and before showing an approval. The F2 port-owner probe, if adopted, belongs at the same
point.

## Answers to the Lead's questions

1. **`reachable: false`:** yes, it's misleading (F9).
2. **Can a checkout redirect `resolve()` away from its metadata?** Not found. `?host=`,
   `?socket=`/`?path=`, percent-encoded, IPv6, NUL-byte and mixed hosts all produce metadata equal
   to the endpoint Bun.SQL dials (repro R1, R6). Bun prefers `path` over `hostname` for both
   adapters, maps a `/dir` hostname to `/dir/.s.PGSQL.<port>`, and lets explicit fields beat
   `PGHOST`, `DATABASE_URL` and `PGSSLMODE` in the Daemon env. The residual risks are F2 (a
   correct address that is really a tunnel), F3/F4 (the target behind a name changes) and F11 (the
   raw URL is still handed out).
3. **Secure Storage across checkouts:** no cross-checkout loss or leak; ids and keys include the
   checkout. Within a checkout, F6 (keep across a target change) and the F13 orphans.
4. **Raw URL text in errors or watch snapshots:** errors are constant. Snapshots carry only
   selected fields, but F5 shows password text reaching `database`.
5. **Checkout identity from `session.cwd`:** no cross-checkout visibility. F13 covers path reuse
   and spelling.

## What was attacked and held

- **No project code runs.** Django and Drizzle use a literal reader that rejects expressions,
  calls and concatenation. Rails ERB other than `ENV["X"]` skips the file. Compose `include`,
  `extends` and `env_file` are not followed.
- **Classification fails safe** for `localhost.evil.com`, `127.1`, `2130706433`,
  `[::ffff:127.0.0.1]`, `0.0.0.0`, `localhost%00.evil.com`, `host.docker.internal` and
  `172.17.0.1`: all `remote`. A remote name aliased to 127.0.0.1 in `/etc/hosts` is classified by
  its name, so `remote`. Only the Host owner can re-point `localhost`.
- **YAML bombs:** nine-level billion laughs in compose took 27 ms and 73 MB. A 21-level merge-key
  chain in Rails took 4 ms.
- **Secure Storage:** `SECRET_VALUE` and the other namespaces are unchanged. Base64 lives only in
  `data/`, and passwords with quotes, spaces and emoji round-trip (D's test).
- **Errors:** every failure maps to constant `DataError` text. There are no event-log writes, and
  `data.sqlite` is 0600 without URLs or passwords.
- **Idle:** no watcher, timer or poll. One sliding PubSub per instance.
- **Grants:** every `data.*` RPC is `client` (Extensions) and `local` (Linked Devices); there is no
  agent path to `save`, `label` or `remove`.
