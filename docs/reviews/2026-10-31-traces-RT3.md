## Findings

### 1. P1: ⌘5 never watches again after a disconnect (CONFIRMED)

Locations:
- `apps/desktop/src/renderer/features/traces/data/hooks.tsx:48` (`useLoaded` re-runs only on `[api, key]`) and `:76` (`useTraces`).
- `apps/desktop/src/main/ipc/traces.ts:49` ("Ends with the connection; the renderer resubscribes").

What happens:
- When the connection drops, the main process ends `traces.watch`, and nothing in the renderer opens it again. The Host's `epoch` and state aren't in the key.
- If the stream ends with an error:
  - The sidebar shows the error text.
  - `setupState` masks it as "Reconnecting…" until the Host is back, then shows "Couldn't read this checkout's traces" for good.
- If the stream ends cleanly, the list freezes: new traces never appear.
- Both cases last until the user switches session.
- The same applies to `TracesMode`'s probe watch and `TraceMain`'s `NoTrace` watch.
- One reconnect, such as laptop sleep or Wi-Fi, is enough. The source is `rule/remote-is-normal`.

Repro, in `mode.test.tsx`:
- "finding 1: after the connection drops and comes back, ⌘5 watches again": no watch is open after the reconnect.
- "finding 1: a watch that ends cleanly on a drop is reopened, so new traces show".

Smallest fix:
- Put the Host's connection `epoch` (`status.epoch`) in `useTraces`' key, as Data's `generation` does.
- Or have `useLoaded` re-run its load when the Host returns to `connected`.
- Keep the last snapshot while the new one loads.

### 2. P1: an open trace is read once, and spans that arrive later never show (CONFIRMED)

Locations:
- `data/hooks.tsx:89`: `useTrace` keys on the trace id only.
- `ui/TraceMain.tsx`: `Open`.

What happens:
- Exporters batch spans: BatchSpanProcessor flushes every 5 s, and a test run sends spans while it runs.
- If the user opens a trace while it is still arriving, the waterfall, the trace bar and "ENDED · n spans" keep the first answer for good.
- Meanwhile the sidebar row's duration and span count, which come from the live watch, move on. The two disagree on the same screen, and nothing marks the trace as incomplete.
- Paper T1's Working strip with "Follow" (finding 24) is the design's answer to this; it isn't built.

Repro, in `mode.test.tsx`: "finding 2: an open trace that is still receiving spans shows the new spans". The waterfall stays at "3 spans" after the summary grows to 6.

Smallest fix:
- In `TraceMain`, read the open trace's summary from the sidebar's snapshot.
- Re-run `traces.get` when its `spans` or `durationMs` changes, keeping the shown detail until the new one arrives.
- Keep the view state (`useTraceView`) across the refresh; today `Shown` is keyed by trace id, so it already is.

### 3. P1: with the receiver Unavailable, listed traces can't be opened (CONFIRMED)

Locations:
- `model/setup.ts:26`: `Unavailable` wins whatever `traces` holds.
- `ui/TracesMode.tsx:68`: the setup state replaces the trace bar, the main view and the span panel.

What happens:
- When port 4319 is taken (`E-TRACE-PORT-IN-USE`), the Daemon still holds and lists the checkout's traces, and the sidebar shows them.
- Clicking one sets the selection, but the main area keeps the Unavailable page, so stored traces can't be read until the port frees.
- DESIGN.md (Traces → Setup) puts the setup page on "With no traces". The `Listening` branch already returns null once traces exist; `Unavailable` doesn't.

Repro, in `mode.test.tsx`: "finding 3: the receiver going Unavailable still lets the listed traces open".

Smallest fix:
- In `fromSnapshot`, return null for `Unavailable` when `traces.length > 0`.
- Show the code, message and owner as a line in the status bar instead (see finding 15).

### 4. P2: an Offline Host reads as Reconnecting (CONFIRMED)

Location: `model/setup.ts:60`. Every state but `connected` maps to `{ kind: "reconnecting" }`.

What happens:
- For an `offline` Host, such as a Pi that is powered off, the main area says "Reconnecting to lucas-rpi…" and "Traces show again once its daemon answers".
- The sidebar header (`ui/sidebar/Header.tsx`) says "· Offline".
- `needs-attention`, such as a changed host key, also says "Reconnecting…", which promises a recovery that won't come without the user.
- Source: `rule/remote-is-normal`, and DESIGN.md's Connection State copy.

Repro, in `model.test.ts`: "finding 4: an Offline Host doesn't read as Reconnecting".

Smallest fix: map `offline` and `needs-attention` to their own setup copy, as Data's sidebar does ("Offline", with the reason), and keep "Reconnecting…" for `reconnecting`.

### 5. P2: exception frames in ⌘5 don't open in the Editor (CONFIRMED)

Locations:

- `ui/TracesMode.tsx:109`: `Workbench` provides none.

What happens:

- T5's claim says the frames open in the Editor. Its test (`ui/SpanPanel.test.tsx`) only checks the frames' order and text, not that they open.
- The code-location pill still works, but error spans often carry no `code.*` attributes. For them, the stack is the only way to reach the code.

Repro, in `mode.test.tsx`: "finding 5: exception frames in ⌘5's span panel open in the Editor". The in-project frame has no `file-link`.

Smallest fix: wrap `Workbench` (or `SpanPanel`) in `<EditorPlaceProvider value={{ hostKey, root: span.polaris.checkout, workspaceId: span.polaris.workspaceId }}>`, or pass `place` to each `FileLink` in `Frame`.

### 7. P2: Open in Data can pick a Remote Data Source (CONFIRMED)

Location: `model/span/dataSource.ts:51`. A null `server.address` or port matches any source.

- A span from a local MySQL database named `analytics` then matches the fixture's `analytics` source, which is `locality: "remote"` and labelled PRODUCTION.

Repro, in `model.test.ts`: "finding 7: Open in Data never picks a Remote Data Source for a span that names no server".

Smallest fix:

### 9. P1: Output's Traces tab loses an earlier Turn's traces after 200 newer ones (CONFIRMED)

- The "was 122 ms" comparison silently goes missing the same way.
- DESIGN.md (Traces → In Orchestrate) makes this tab where a Tool Call's trace chip leads.

Repro, in `mode.test.tsx`: "finding 9: Output's Traces tab counts an earlier Turn's traces after 200 newer ones". It gets null (no tab) where it should count 1.

Smallest fix:
- Watch with `filter.turn` set to each shown Turn's id (the protocol supports it), and use `total` for the count.
- Read the comparison runs with a separate `route` filter for the listed roots.

## Attacked, no finding

- **Capability-less Daemon.** ⌘5 is disabled with a reason, and the mode shows "Traces need a newer daemon on ‹host›". Output's tab watches nothing; T5's `output/tab.test.tsx` covers this, and it passes.
- **Re-render cost while snapshots arrive** (`perf.test.tsx`, happy-dom, React Profiler, 40 snapshots). One unchanged snapshot costs a median of 0.42 ms with nothing open and 0.82 ms with the 10,000-span trace open, in one commit. At 4 per second that is under 0.5% of a frame budget.
- **10,000-span trace in Electron** (T4's script re-run, Midnight, calm, this Mac):
  - Opens in 50.5 ms; Expand all takes 10.5 ms.
  - Scrolling: median frame 5.6 ms, p95 6.5, p99 6.8, max 10.9 ms.
  - 1 of 600 frames was over 1.5× the median, with 54 DOM rows. That meets the ≥120 Hz budget.
- **Leaks on fast session or Host switches.** `Shown` is keyed by Host and session, and unmounting closes every watch. `openTrace` is unpublished on unmount. The selection store keeps one small entry per session visited, which is negligible.
- **30-service trace.** The Services popover scrolls (`max-h-(--radix-popover-content-available-height)`). Services after the fifth take the neutral hue by design (DESIGN.md, Waterfall) and are named in the popover.
- **Glossary.** A grep of every user-facing string in `features/traces` found glossary words lowercase mid-sentence ("agent session", "daemon", "turn"). Capitals appear only at sentence starts and in kickers.
- **Both themes and all three densities.**
  - 87 screenshots: Moonlit, Midnight and light, at calm, balanced and compact.
  - Rows follow `--spacing-tree-row`.
  - The trace bar (34px), toolbar (44px) and span panel header are fixed by design (Paper T1).
  - Findings 14, 16, 19 and 20 are the visual issues found.
- **Reduce Motion.** The view has no motion of its own; the popover and toasts come from `@polaris/ui`.
- **-cvd.** No diff tokens are used in Traces; finding 14 covers the one colour-only cue.
- **⌘L.** It appends after the draft and stops at `MAX_DRAFT_LENGTH` with a toast. Session attribution is finding 8.
- **Redaction.** `"[redacted]"` reads faint wherever it appears (T5's test). The endpoint token isn't shown in any view except the empty state's copy line, by design.

## Not done

- **No live Daemon.** Every check ran on T3's fixture API, the scripted API in `harness.tsx`, and the preview scenes. Findings 1 and 2 are confirmed against the main process's documented stream ending (`main/ipc/traces.ts:49`), not a dropped socket.
- **Not measured:**
  - Workspace switch time.
  - Total app memory with the 10,000-span trace open.
  - Any run on a Pi or a VM; this is a renderer-only change.
- **No new scenes for the PLAUSIBLE cases.** Deep trees, a 1,000-log span, 40 failing traces and non-Latin or bidi span names weren't rendered, because that needs preview scenes in product code.
