# Adversarial review: Review's Data section and Output's Data tab with the write card (ENG-645)

Reviewed at `ad3aee73`. In scope: RV (`bd63d8da`), OD (`6bf2c52c`), WF's protocol fields (`e6f3948c`),
SDF's Schema Diff fields (`e57c3c74`) and RVF's labels (`ad3aee73`). Code read:
`apps/desktop/src/renderer/features/data/write/`, `data/output/`, `review/schema/`,
`needs-you/respond.ts`, `shell/approvalInView.ts` and `store/sessionModel.ts`. The Daemon paths behind
them were read too: `data/writeExecution.ts`, `writeQueries.ts`, `queryLog.ts`, `mcp/tools/data.ts`
and `engine/session.ts`. They were checked against DESIGN.md → Data, the Daemon's data README and
`packages/protocol/src/schemaDiff.ts`. Reviewer: RRV (RU1), Opus 5.5, 2026-10-31. No product code
changed.

**Verdict.** Schema Diff follows SDF's semantics. Exact counts say "matched by writes through
Polaris", unknown is never 0, the baseline captions match the protocol, and concurrency is a caveat
rather than a claim. Deny needs a reason, and the reason reaches the agent. Frame rate and memory
are fine. Three things need fixing before writes ship:

- A Local Postgres DDL card names the wrong reason: "Not previewed: this table has triggers" (F1).
- ⌘⇧A, the inbox and notifications run a write when only 1 px of its card is on screen. That
  includes when just the Run button is showing (F2).
- A write that changes a credential column shows no changed cell, so it reads as a no-op (F3).

### F1. The DDL card gives the trigger reason (P1)

WF skips the preview for every Local Postgres DDL statement. Its `note` is "Not previewed: this
statement changes the schema", and `previewed` is false. `dryRunKicker` returns the constant
`NOT_PREVIEWED` = "Not previewed: this table has triggers" whenever `previewed === false`. The note
is hidden only when it equals that constant, so the DDL card shows both lines:

```
DDL kicker: Not previewed: this table has triggers | note shown: true | run: Run without preview
```

The user is told about triggers on a statement that has none, then contradicted one line later.
They can't tell why there's no preview. Rules: rule/say-what-happened, rule/point-at-risk.
**Fix:** when `previewed === false`, take the kicker from `write.note` (the Daemon sends the reason),
drop the separate note, and test both reasons.

### F2. A write runs with its SQL off screen (P1)

`approve()` refuses a write unless `isApprovalOnScreen(id)`. `onScreen` checks only
`rect.bottom > 0 && rect.top < innerHeight`. It ignores the conversation's scroll viewport (whose
bottom is at 745 px, under the composer, in a 900 px window), and any 1 px counts. In the probe,
the 1,204,118-row card was scrolled until only its last 40 px showed: the Deny and Run row, with
the SQL, rows and kicker above the fold. The guard passed. ⌘⇧A, the inbox's Approve or a
notification would then run the write. A card scrolled under the composer passes too. Worst-case
cards are 1,132 px tall, so the SQL and the Run button never fit on screen together.
`approve-guard-40px.png` shows that state.

This breaks OD's own decision ("never run a write the user hasn't seen") and rule/point-at-risk.
**Fix:** measure the card's header through its kicker (SQL, params, "Dry run"/"Not previewed")
against the conversation scroller, with an IntersectionObserver rooted there. If that part isn't
fully visible, scroll the card's top into view and focus it instead of sending. Test with a card
that is partly visible.

### F3. A credential column change looks like no change (P1)

WF redacts cells by column name before persisting them (`writeExecution.ts:222`), and both images
become the string `"[redacted]"`. `cellChanges` compares them as equal:

```
update users set password_hash = $1 where id = $2
redacted changes: [["same","same"]] | changed cols: []
```

The card shows a one-row update whose cells are all unchanged, so the user approves something that
looks harmless. `changedColumns` also leaves the column out, so a wide table doesn't lead with it.
`"[redacted]"` is drawn as ordinary text, so it's indistinguishable from a real value. Rules:
rule/say-what-happened, rule/point-at-risk. **Fix (protocol + Desktop):** send redaction as a
typed value that records whether the cell changed, for example a `Redacted { changed }` tag. Render
it as a placeholder ("redacted · changed") in the diff colours.

### F4. The riskiest card looks like the others (P2)

A write the Daemon couldn't preview gets the faint 11 px uppercase kicker every dry run gets.
"Run without preview" is the same primary pill as "Run 214-row update", in OD's own screenshot. A
trigger's or DDL's effect is the one thing this card can't show. Rule: rule/point-at-risk.
**Fix:** put the not-previewed kicker in the Needs You text tone and add one plain line under it:
"Polaris can't show which rows this changes." Keep the button's label; that already says it.

### F5. Outcome unknown (P2)

```
{"line":"1-row update: outcome unknown",
 "detail":"The connection dropped before the database answered. Check the table before running it again."}
```

- The Daemon also marks writes unknown on recovery after a restart (README: "Recovery marks
  unfinished writes unknown"), when no connection dropped.
- "Before running it again": the Daemon refuses to dispatch an unknown request again. A retry
  needs a new preview and approval.
- `SettledIcon` and the Data tab's `StatusIcon` draw nothing for unknown. The one state that
  needs the user's attention is quieter than "Ran ✓".
- The settled card has no way to the rows the user is told to check.

Rules: rule/say-what-happened, rule/point-at-risk. **Fix:** "Polaris lost track of this write
before the database confirmed it. Check the rows before asking the agent to try again." Add an icon
in the Needs You or failed tone, and "Open in Data" on the settled line, aimed at the write's table.

### F6. Expired and withdrawn states say the wrong thing (P2)

`ApprovalWithdrawn` carries a `reason`, but `WriteOutcome` keeps only `by`. Daemon withdrawals
include "Interrupted" (the user's Stop), "The session was archived" and Harness error messages
(`engine/session.ts:288,313,541`). All of them render as "Expired: the daemon restarted before you
answered". After a reload, settled writes are gone, and the Daemon's Query Log maps a withdrawn
write to `failed` and `denied`. The Data tab then shows "Denied: The Turn ended", which says the
user denied a write they never answered. Rules: rule/say-what-happened,
rule/design-reachable-states. **Fix:** keep the withdrawal's reason in `WriteOutcome` and render
"Expired: <reason>". In the Daemon, store withdrawn writes as their own status (for example
`expired`), so the Query Log doesn't read them as denials.

### F7. The deny reason reaches the agent with "Don't retry" (P2)

`awaitApproval` returns the user's reason, and `mcp/tools/data.ts` sends it as
`E-DATA-DENIED <reason>` with the fix "Don't retry; ask the user." The card's field says "Tell the
agent why, so it can try another way". The user writes "use EUR, not USD", and the agent is told
not to retry. Rule: rule/say-what-happened. **Fix (Daemon):** when a write is denied with a user
reason, use the fix "Read the user's reason; a different write needs a new preview."

### F8. The Daemon's note is shown verbatim (P2)

Real previewed cards end with "Up to 20 rows, read by primary key; preview capped at 16,000 bytes.
Sequence values used by the preview aren't reused." The text also gains "Some rows or columns were
omitted by the result budget." when clipped. That is implementation detail (rule/copy-no-rationale),
and the sequence sentence appears on UPDATE and DELETE too. OD's fixture used its own sentence,
so no screenshot shows the real text. **Fix:** send typed facts (`sequences: boolean`,
`clipped: boolean`) and let the Desktop App word them. Show the sequence note only on an INSERT
into a table with database-filled columns: "IDs the preview used are skipped; the run gets new
ones."

### F9. INSERT previews show values the run won't use (P2, plausible)

`insertedPreview` returns the dry run's inserted rows as they were, including serial, identity and
default columns. WF excludes those columns from the identity hash but not from the display, so
the card shows `id 41` and the real run gets 42. Rule: rule/say-what-happened. **Fix:** have the
Daemon mark database-filled columns (it already knows them for the identity), and have the card
dim those cells with "assigned on run".

### F10. "Sch…" (P2)

The lead noted this in RVF's `-worst`. It is measured at every density (Calm 21 px, Balanced 37 px,
Compact 53 px of the 68 px label). The label is `min-w-0 flex-1 truncate` while the four counts are
`shrink-0`, and "+ others" shrinks with it, so the fixed noun gives way first. See
`schema-label-calm.png` and `schema-label-compact.png`. Rule: rule/long-content-survives.
**Fix:** make "Schema diff" `shrink-0`. Let "+ others" go first (its sentence is already the
tooltip), then fold the counts into one total, or into a second line when the row is narrow.

### F11. "Open in Data" can open the wrong table (P2)

- A write with no `affected` (waiting, failed, unknown) falls back to `tableOf(sql)`, which keeps
  only the last name part. `update billing.invoices …` opens `public.invoices`, which may be a
  different table or none.
- The schema card opens `diff.tables[0].after ?? before`. When the first table was removed, that
  is a table that no longer exists. RV's per-table "Open in Data" already skips removed tables.

Rule: rule/say-what-happened. **Fix:** return the schema from `tableOf`, and pick the first table
that isn't removed.

### F12. "Schema diff" from the Data tab opens a different Turn (P2)

`schemaDiff` calls `openSessionReview` (subject only) and `openSchemaDiff(key, sourceId)`. No Turn
pick is passed, so Review shows "All turns" or the last-picked Turn group. That view has a
different provenance and different counts from the Data tab the user came from. The tab's own
diff asks for `turnIds[0]`, so schema changes in continuation Turns are missing. RV listed this,
and it now affects a second surface. **Fix:** pass the Turn group to Review's picker. Have the
Daemon (or the Client) merge the group's Turns, per RV's follow-up.

### F13. Params bypass the credential-column redaction (P2)

Rows redact `password_hash`, but the bound value is printed as `$1 = $2b$10$newhash` and persisted
in the `ApprovalRequested` event, which goes to every Client: phone, glasses and inbox.
**Fix (Daemon):** for UPDATE and INSERT, map each param to the column it's assigned to. Redact
params bound to credential columns, as the rows are.

### F14 to F17 (P3)

- **F14.** "table_003 rows 9" can be read as the table's size. Make it "9 matched". "~−1" puts
  the tilde against the minus; try "−1 est." with the statistics tooltip.
- **F15.** Drop the ⌘4 Kbd from targeted "Open in Data" buttons, or put it in the tooltip
  ("Data ⌘4"). ⌘4 doesn't open the table.
- **F16.** Read `write.params`, `write.previewed` and the typed `"unknown"` state directly. Delete
  `WfFields` and the string widening, as OD's follow-up asked.
- **F17.** The pixel moon sits over the last rows of a long files list. Stop the list above the
  scene, or fade the scene under scrolled content (rule/scene-text-contrast).

## Checked and holding

- **Schema Diff and SDF.** Exact counts read "N rows matched by writes through Polaris" with the
  footnote. Estimates are marked "~" and "estimate". Unknown reads "Rows: unknown" and keeps a
  known split, never 0. Concurrency is a caveat ("Includes changes from other sessions…"), never
  attributed to the Turn. Baselines: "Since the end of the previous turn"; a carried baseline reads
  "Since turn N · <relative>" with the absolute time as the title; first-use wording; pruned history
  is called out rather than shown as an empty diff.
- **Deny.** The reason is required (Deny is disabled while it's empty), is trimmed, and is sent as
  `Deny({reason})`. The Daemon stores it and returns it to the waiting tool call (see F7 for the fix
  text). Writes never offer Always Allow. Run sends `Allow({remember:false})`.
- **The card.** The verb and count come from the SQL and `affected`. INSERT says "N new rows" with
  an empty before image. Params are listed (`$1 = …`). The remote label colour is on the top bar.
  SQL folds at 6 lines or 600 characters behind "Show the whole statement". 256 columns and huge
  cells scroll inside the card without frame loss.
- **Data tab grouping.** Entries are filtered to the shown Turn group's ids and the session, dry
  runs folded, oldest first. Reads fold to "n reads · Query log", which opens the log filtered to
  the Turn. The tab is absent without data or the capability.
