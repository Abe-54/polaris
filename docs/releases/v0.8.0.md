Agents can now see your data and your running app. **Data (⌘4)** is a SQL client scoped to each agent session: it finds the session's Postgres and MySQL databases from its checkout, lets agents read them over MCP, and puts every write behind an approval with a dry run. **Traces (⌘5)** receives OpenTelemetry from the apps your agents run, so you and the agent see the same requests, errors, CPU profiles and before-and-after timings, per Turn.

## What's new

### Data (⌘4)

- **Data sources found for you.** Each session's checkout is scanned for database URLs (`.env` files and common configs), so a branch database opens without setup. Add or label sources by hand too. Postgres and MySQL to start.
- **Browse and edit.** A sidebar of schemas and tables, a table grid with filters, Data and Structure views and ⌘L to send rows to the session. The SQL tab completes table and column names as you type.
- **Agents query, read-only by default.** The `data_sources`, `describe` and `query` tools let an agent see the real schema and rows instead of guessing. A session's first read of a data source asks you once (a Data Source Approval).
- **Writes wait for you.** An agent's write runs as a dry run first; the approval card shows the statement and the rows it would change. Grid edits are staged and committed with ⌘S, with a confirmation for bulk changes on a remote database.
- **The Query Log** lists every query each agent ran, with its result, and runs any of them again.
- **In Review and Output.** Review's Data section shows the Schema Diff each Turn made. Output's Data tab shows an agent's data changes, with **Open in Data**.

### Traces (⌘5)

- **Your app's telemetry, per session.** Each agent session gets an OTLP endpoint. Requests from the apps it runs land in ⌘5 as a trace list, a waterfall and a table, with each span's code location, errors and correlated logs, attributed to the Turn that launched the command.
- **Agents read traces.** The `traces`, `trace` and `span` tools let an agent check what its change actually did; `compare` shows each route's p50 and p95 before and after a Turn.
- **Set up tracing.** Node and Deno apps are instrumented automatically when you turn it on in Settings → Traces; an app with its own OpenTelemetry setup keeps it. **Set up tracing** installs the polaris-tracing skill and asks an agent to add tracing to the project.
- **Your collector keeps its data.** If the session's environment already sends telemetry somewhere, Polaris forwards a copy there. A collector named only in a repository file is a suggestion until you save it, and your shell's credentials only go to the collector you launched with.
- **CPU Profiles.** **Restart with profiling** restarts a server the agent started and records it; a running Node process can also be profiled in place. The flame chart opens on the stretch that overlaps the trace you were looking at, and frames open in the editor. The agent's `profile` tool records the same way; profiling a running process asks you first.
- **Service map.** A third view draws one trace's services and the calls between them, with N+1 calls flagged.
- **Route timings in Review.** Review's Traces section shows each route's p50 before and after the Turns under review.

### Desktop

- **The Constellation tab** hangs a Task under the sibling it depends on, as a tree.
- **Advanced view** (Settings → Sessions) shows each reply's latency, tokens and tokens per second.
- **Steer with attachments.** Images and files sent while a Turn is working go in with the steer instead of waiting in the queue.
- **Several questions at once:** a typed answer answers only the question on screen.
- **Host stats** show after the first watch, not only on a freshly started daemon.
- The sources pill sits across from the Turn's avatars, auto mode has its own glyph, and the Working strip no longer scatters.

### Your hosts

- **On the Mac, the daemon is an app named Polaris,** so System Settings shows the Polaris icon in permission prompts and Login Items.
- **The trace store** keeps 200 MB or seven days per checkout, errors always, and wakes only when traces arrive.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.8.0-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.7.0 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.8.0 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.8.0-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.8.0 the next time it connects. Data and Traces need the host on 0.8.0.

## Known limitations

- Data supports Postgres and MySQL only; SQLite comes later.
- Data and Traces are in the desktop app only, not yet on the iPhone.
- Automatic instrumentation is for Node and Deno; Bun apps use the polaris-tracing skill.
- Commands an allow rule approves without asking aren't traced per command.
- Profiling a running process in place fails while another program holds port 4319, and misses a hot loop that was already running before the capture started; **Restart with profiling** covers both.
- 0.3.0's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.3.0) still apply.
