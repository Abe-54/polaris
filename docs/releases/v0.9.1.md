0.9.1 closes a gap in how Requests asks for approval, fixes a rare stall in the daemon, makes the daemon and the app faster, and gives the app's chrome its first morphs: the editor's terminal now divides out of the editor card.

## What's fixed

- **A request approval covers only the agent session that asked.** In 0.9.0, while one agent session's send to another origin waited on its approval card, a second agent session's send to the same origin joined that card instead of asking for its own. A one-time allow of the first card then let the second send go out too, though the card named only the first. Each agent session now gets its own card and goes to needs you. An approval you remember is unchanged: per host and origin, for every agent session. If your agents send requests to other origins, move your hosts to 0.9.1.
- **The approval card names the token.** When a send carries a masked variable, the card has a **Token** row with the file and the variable's name, and says "Agents never see the token."
- **A rare stall in the daemon.** A change that arrived just as the daemon finished writing the ones before it could sit unwritten until the next change came in. On a quiet host that could leave a command unanswered or a turn's end unrecorded.
- **Suggested replies come back after you sign in to a harness.** They resume within a minute, without restarting the daemon, and a plan limit warning no longer stops them.
- **The composer checks spelling** on Mac and Windows, with corrections in its right-click menu.

## Faster

- **Starting a daemon with a long history.** The reads at start no longer scan the whole log: on a 2.5 GB log the store is ready in about 45 ms, was about 365 ms. The first start on 0.9.1 builds two indexes once, which takes up to about 7 s on a log that size.
- **Checkpoints and diffs** run fewer git commands: a working-tree diff takes about 80 ms, was about 115 ms.
- **Very long lines from a harness** no longer slow the daemon: a 16 MB line is read in about 2 ms, was about 100 ms.
- **Long agent sessions scroll and type more smoothly.** The turns rail, the composer's sent history and live command output no longer rescan on every frame. Live output shows its last 256 KB.
- **The app saves its cache of each host every 30 s** and when you leave the window, instead of every 2 s.
- **Switching to Review, Edit, Data, Traces or Requests for the first time** shows that mode's frame at once instead of a blank window.

## Motion

- **The editor's terminal divides out of the editor card.** Showing the terminal (⌃`), the card's foot splits: the terminal rises out of the status bar and the bar's corners round as it lifts off. Hiding it joins them back.
- **The selected pill slides** between segments in every segmented control, such as the mode switch.
- **Popovers and menus open from the control that opened them.**
- **Every disclosure turns the same chevron,** and a folded file header in a diff rounds its corners instead of snapping.
- With **Reduce Motion** on, none of this moves: the terminal crossfades and the rest changes at once.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.9.1-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.9.0 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.9.1 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.9.1-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.9.1 the next time it connects. The approval fix and the daemon fixes need the host on 0.9.1.

## Known limitations

- The terminal's morph is in the editor only; the terminal drawer under an agent session is unchanged.
- 0.9.0's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.9.0) still apply.
