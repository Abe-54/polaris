Agents can now use the apps on your hosts. With **computer use** on for a host, Claude Code and Codex sessions can see an app's windows, click and type in them, with your approval for each app, and you can watch the window live from the transcript. This release also adds **Requests (⌘6)**, an HTTP client linked to Traces and Data, puts iOS Simulators and Android Emulators in the Output, and can offer a suggested reply when a turn ends.

## What's new

### Computer use

- **Agents operate desktop apps.** Each agent session on a host with computer use on gets the `polaris_desktop` tools, in Claude Code and Codex. They are built on agent-desktop (vercel-labs, Apache-2.0), which Polaris installs and keeps pinned on each host. Codex's own computer use is turned off; Polaris applies its rules whatever permission mode the session is in. Read-only sessions and the reviewer don't get the tools.
- **On or off per host.** Settings → Hosts has a **Computer use** card with a switch, the host's status and what's still missing. On a Mac, setup is one step: **Open System Settings** opens the privacy pane and shows **Polaris Computer Use.app** to drag in. If only Accessibility is granted, the step becomes **Allow Screen Recording**. A remote Mac's settings open on that Mac. A Linux host needing setup names the package to install (`at-spi2-core`) and the command to run there. A host with no desktop session says so.
- **A separate helper app on macOS.** Accessibility and Screen Recording belong to Polaris Computer Use.app, not the daemon, so the grant covers computer use only and nothing else the daemon starts. The helper runs tools only for the signed daemon.
- **Set up as you go.** On this Mac, an empty workspace shows a card, "Let agents use apps on this Mac", which you can skip. When an agent needs computer use while it's off, the session goes to needs you with a card in the transcript showing the fix for this host, and **Not now**. Once the host is ready, the agent gets its tools on its next turn.
- **You approve each app.** The first time an agent session uses an app, you choose **Allow once** (for this agent session), **Always allow on ‹host›** (every agent session there), or **Deny**. Real pointer and keyboard input (headed input) is approved separately, per app and per agent session, and can never be always allowed.
- **Some apps are refused.** Terminals, script runners, System Settings, Keychain Access, Passwords, password managers and Polaris itself are never offered to agents. **Allow an app…** in the host's Computer use card is the only way to allow one, after a warning. It also lets you always allow an app before an agent asks. Always-allowed apps are listed there, with **Remove**.
- **One agent session per app.** While one session controls an app, another session's call on it is refused ("In use by ‹session›"). The app is released when the turn ends.
- **Watch it work.** A computer use step reads "Using ‹app›" and ends in a window thumbnail. Hover it for a live view of the app's window (never the whole screen); Space on a session row shows the same view. The host captures only while you're watching.
- **Approvals on every client.** The iPhone shows app and headed-input approvals under needs you and in the thread, next to the agent's last frame. The Even G2 glasses ask "Use ‹app›?" with **Allow once** and **Deny**. Extensions built on `@polaris/sdk` can opt in to these approvals; no extension can always allow an app.

### Requests (⌘6)

- **A small HTTP client for your checkout.** Requests lists the `.http` and `.rest` files in the agent session's checkout (VS Code REST Client and JetBrains format), with Params, Headers, Body and Auth, `{{variables}}` from `http-client.env.json` and `.env` (secrets masked), **Copy as curl** and curl import. **Send ⌘↵** sends from the host.
- **Linked to Traces and Data.** Each send shows its response, the trace it started, live, and the tables it read or wrote, with **Open in Traces** and **Open in Data**. A trace that a send started gets **Resend in Requests**.
- **The send log** lists every send in the checkout, yours and your agents', with who sent it and in which turn. Open one to send it again.
- **Agents send too.** The `send_request` tool lets an agent call your app. Sends to the host itself go straight through. A send to any other origin waits for your approval, remembered per host for reads only or for reads and writes. Your own sends never ask.

### Simulators

- **iOS Simulators and Android Emulators in the Output.** A Simulator tab after Browser streams the device from the host, with home, rotate, screenshot and restart, and a picker for every Simulator on the host. It works on remote hosts too.
- **Agents drive them.** Claude Code and Codex sessions get the `polaris_simulator` tools to open a Simulator, tap, type, swipe, take screenshots, launch apps and open URLs. The tab shows when an agent is driving.
- **Setup and idle.** A host without Xcode or the Android SDK says what's missing. On a Mac, first use downloads the Simulator's tools and a pinned copy of Bun. Simulators that Polaris booted shut down after 5 minutes with nobody watching and no agent using them.

### Suggested replies

- **A reply in the empty composer.** When a turn ends, the composer can offer one suggested reply where the placeholder would be. Tab types it in; nothing is sent until you press ↵. Typing or esc dismisses it.
- **Off by default.** Turn it on in Settings → Sessions → Suggested replies; the setting goes to every host. Polaris writes each suggestion with a small request on the cheapest fast model that's ready, or one you pick there. There's no suggestion on the first turn, after a failed or interrupted turn, in plan mode or near a plan limit.

### Desktop

- **Archived sessions** sit in a folded "Archived" section at the end of the sidebar, with **Unarchive**. Archiving shows a toast with **Undo**.
- **F2** renames the focused session row in place.
- **Localhost links in a reply** open in the agent session's Browser.
- **Answer a worker's question from the lead's chat.** Open questions are pinned above the lead's composer.
- **Browser picks carry the React component** and where its JSX was written.
- **Traces' Working strip** shows while a session works; **Follow** opens each new trace of the turn.
- **Codex fast mode** can be chosen for constellation workers.
- **gD** goes to the declaration, where the language server supports it.
- The composer says "Draft saved" once the host holds the draft.
- Sent messages keep their Skill, command and file chips.
- Markdown tables are as tall as their rows.

### iPhone

- **Steer with attachments** while a turn is working, where the host and harness take them.
- **Retry and Continue** from an agent session's menu, and **New agent session on ‹host›** from a host's menu.
- **A notification switch per host**, on the host sheet. Failed turns, and a constellation's failed attempts, now push.
- **Review while a host is away** says why instead of showing an empty turn.
- The file diff screen rotates to landscape.

### Your hosts

- **Approvals need the desktop app.** Before, any process on the host, an agent's own shell included, could connect to the daemon and approve its own requests. Approving, starting turns, changing permission modes, providing secrets, accepting work and typing into terminals now need a key held by the desktop app; the iPhone and extensions keep their own permissions. The first desktop app to connect to a host holds it. `polaris extension pair` and `revoke` now point you to Settings → Extensions.
- **A harder daemon on macOS.** The signed daemon ignores `BUN_BE_BUN`, `BUN_OPTIONS` and `BUN_INSPECT`, and loads native libraries only from its own app bundle. The desktop app refuses Node mode (`ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS`, `--inspect`).
- **The relay is now written in Rust.** The relay between the iPhone and your hosts batches its writes and limits connections that haven't finished connecting.
- **OpenCode** reports context usage and compacts, so idle compaction covers it.

## What's fixed

- **A steer the harness refuses** stays in its turn, marked refused, with the harness's reason. Before, it vanished.
- **Claude's tokens per second** count hidden thinking as generation, so a reply no longer reads as 18,000 tok/s.
- **Links open in your browser.** HTTP and HTTPS links, localhost included, open externally from the conversation and the context menu. Images in Windows paths show in the transcript and the viewer.
- **Data:** the grid's header stays as wide as its columns, Structure is syntax-coloured, and ⌘W closes the tab instead of the window.
- **Memory after a burst of file reads** is released once the daemon goes quiet.
- **Accept** refuses a lead branch that another session's worktree has checked out.
- **After a daemon restart,** live sessions' browsers keep working with new tokens, and a needs you held back from the iPhone while you're at the Mac still reaches it.
- **Codex** is found each time it's used, so one installed after the daemon started works; a miss names the PATH searched.
- A successful Claude Code Bash step records exit 0. A stuck `lsof` can't hold up daemon start. A canceled file search stops its `git grep`. File watches on macOS keep working after Bun rebuilds its stream.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.9.0-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.8.5 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.9.0 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.9.0-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.9.0 the next time it connects. Computer use, Requests, Simulators and suggested replies need the host on 0.9.0.

## Known limitations

- **One desktop app per host can approve.** A second desktop app (say, on another Mac) connecting to the same host can't approve or start turns there. To move access to it, delete `~/.polaris/user-access.json` on the host and reconnect.
- **Computer use:**
  - **Allow an app…** on a remote host takes the app's id as text (bundle id, `.desktop` id or `.exe` path); only this Mac has a picker (ENG-883).
  - The live view is macOS only. Linux and Windows hosts show the last frame the agent saw, and none on Wayland outside GNOME.
  - Computer use hasn't been tested on Windows hosts yet. On Linux and Windows, apps are known by name, so the refused list matches by name (ENG-882).
  - Approval cards don't show the app's icon yet. Headed clicks are checked against the window list, so another app's always-on-top window isn't seen, and your taking over the mouse or keyboard is noticed between actions only, on macOS only (ENG-882).
  - Live view on a locked screen, and on a Mac with nobody logged in, hasn't been checked on real hardware (ENG-879).
  - The helper should keep its permissions across updates; this is the first release that ships it. If computer use asks for setup again after an update, drag the helper in again (ENG-868).
  - The release pipeline checks only the version line of the signed daemon's self-test (ENG-881).
- Suggested replies come from Polaris's own request for every harness, Claude Code included, until Claude Code sends its own (ENG-891). They can come from another vendor's model than the session's, and aren't counted in the session's usage.
- Requests, Simulators and computer use's live view are in the desktop app only. Requests shows the tables a send touched, not rows (ENG-812).
- The Lock button is hidden for iOS Simulators, which iOS 27 ignores.
- OpenCode 2 isn't supported yet; the host says so with the installed version.
- HTML files on a host still open as source in the editor (ENG-819).
- 0.8.5's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.8.5) still apply.
