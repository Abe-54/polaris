Constellation workers waiting on background work are no longer reported as stopped, a crash no longer blanks the whole window, and the images agents look at show in the conversation. In developer mode, agents get new tools for reading Polaris's own traces.

## What's fixed

- **Workers waiting on background work aren't "stopped".** A Claude Code worker that ends its turn to wait on a background command, a monitor or a background subagent shows as **waiting on a command** (or subagent), with how long. Its lead isn't told it stopped, and it isn't nudged or flagged as stalled. A worker can also say what it's waiting on and roughly until when. If the work ends and nothing follows within 2 minutes, or after an hour, the usual checks resume.
- **A crash stays in its pane.** An error in Review, an agent session, Data, the editor, Traces or Settings now shows "… hit an error" with **Reload** and **Copy details** in that pane. Before, it turned the whole window black. Crashes are written to `crashes.log` in Polaris's logs folder (`~/Library/Logs/Polaris` on Mac, `%APPDATA%\Polaris\logs` on Windows).
- **Going back to Findings after asking the reviewer** no longer blanks the window.
- **Developer tools in every build.** **Help → Toggle developer tools** (⌥⌘I, or Ctrl+Shift+I on Windows) opens them.
- **Images agents view show in the conversation.** A screenshot an agent opens (Codex's `view_image`, or Claude Code reading an image) shows under its step, and clicking it opens the viewer. Markdown links in a reply to files on the host open in the viewer or the editor. Images an agent only passes to itself, such as `image()` inside Codex's exec, still can't reach you, and agents are now told so.
- **The reviewer on Linux hosts with Codex installed in your home folder** can run commands in its sandbox. When the sandbox can't start, or Codex isn't installed, the review now says so instead of reporting **Reviewed**.

## Developer mode

- **New trace tools for agents:** `trace_capture` records what happens while you reproduce something; `trace_stats` gives counts, errors and durations by span; `trace_errors` groups errors by message; `trace_compare` compares two time windows or two builds. `traces` and `trace_stats` filter by span attribute.
- **Richer self-traces.** A root span for each action you take in the app, with the requests it causes under it. Data requests name their source and table. Warnings and errors are recorded with secrets redacted. The daemon's error stacks name source files and lines.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.8.5-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.8.4 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.8.5 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.8.5-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.8.5 the next time it connects.

## Known limitations

- Linux hosts with bubblewrap older than 0.9 (such as Ubuntu 22.04) still can't run the reviewer's commands with Codex; the review says so (ENG-760).
- HTML files on a host open as source in the editor, not in the app's browser (ENG-761).
- 0.8.4's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.8.4) still apply.
