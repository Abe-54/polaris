0.9.2 lets every desktop app you use reach a host again. In 0.9.0 and 0.9.1, only the first desktop app to connect to a host could approve, send turns or start agent sessions there. Suggested replies also show up after most turns now, instead of now and then.

## What's fixed

- **A second desktop app is no longer locked out of a host.** A host accepted user-only actions (approvals, turns, new agent sessions, permission modes, secrets, pairing) only from the first desktop app that connected to it. Any other one got "another one holds user access", for example the app on a Mac you also use as a host, when your laptop had connected first. Deleting `~/.polaris/user-access.json` only moved the lockout to the other app. Every desktop app now works on every host it connects to, and the host ignores that file.
- **`polaris extension pair` and `polaris extension revoke` work from a terminal again.**

## Suggested replies

- **A suggestion after most turns.** The suggested reply is the message you're most likely to send next, and it's left out only when there's nothing to send. The first turn of an agent session gets one too.
- **In your own words.** To match how you write, the model that suggests replies sees up to 30 of your recent typed messages from your other agent sessions, each cut to 280 characters. Messages from workers, reviewers and triggered turns are left out.
- **Any ready model.** The model you chose in Settings is tried first, then each automatic pick (Codex, then Claude). One that's signed out, failing or at a plan limit hands over to the next.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.9.2-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.9.1 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.9.2 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.9.2-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** Both changes are in the daemon, so each host needs 0.9.2. With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.9.2 the next time it connects.

## Known limitations

- 0.9.0's protection against a process on the host answering approvals is off again: a program with access to the daemon's socket, including an agent's own shell, can approve its own requests, as before 0.9.0. It comes back in a later release, with a way to allow each of your desktop apps on a host.
- 0.9.1's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.9.1) still apply.
